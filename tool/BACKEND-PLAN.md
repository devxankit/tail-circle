## Locked Decisions

| Area | Decision |
|---|---|
| Stack | Node.js + Express 5 + MongoDB (Mongoose 9) — already scaffolded in `backend/` |
| Auth | Phone OTP (users) via **SMS India Hub**, email+password (vendors/admin), JWT access (15m) + refresh (30d) rotation |
| Payments | **Razorpay** (orders + signature-verified webhooks), ₹ currency |
| Real-time | **Socket.IO** mounted on the HTTP server from Phase 0 (live tracking, kitchen/delivery boards, notifications, video signaling) |
| Messaging | **Socket.IO** is the live transport for chat messages (user↔user match chat, shelter chat, clinic messages); MongoDB is the source of truth for history, search & moderation. _(Migrated off Firebase Realtime Database on 2026-07-23 — RTDB code removed; Firebase now used for FCM push only.)_ |
| Caching | **Redis** — catalog/response caching, dashboard aggregation cache, OTP cooldowns, rate-limit store, idempotency keys, Socket.IO adapter for horizontal scaling |
| Media | Cloudinary (already wired) via multer memory upload |
| Push | **Firebase Cloud Messaging** (device tokens per user) |
| Validation | Zod schemas on every write endpoint |
| Build order | User app → Vendor portals → Admin panel → Hardening |

## Architecture Conventions (apply to every module)

- Module layout: `src/modules/<name>/{<name>.model.js, .validation.js, .service.js, .controller.js, .routes.js}`
- All responses via `ApiResponse`, all errors via `ApiError` + central handler, all async via `asyncHandler`
- RBAC: `requireAuth` → `requireRole('user'|'vendor'|'admin')` → ownership check in service layer
- Every list endpoint: pagination (`page`, `limit`, max 100), sorting, filtering; indexed query fields
- Money is stored in **paise (integer)** to avoid float errors; convert at the API edge
- Status fields are enum-driven state machines; transitions validated in services, never trusted from the client
- Soft delete (`deletedAt`) for user-facing content; hard delete only for admin catalog rows
- **Caching policy (Redis):** cache public catalog reads (products, providers, plans, breeds, banners) with short TTLs (60–300s) + explicit invalidation on admin/vendor writes; cache keys namespaced `tc:<module>:<hash>`; never cache user-private or payment data
- **Chat data policy:** messages persist to MongoDB (source of truth for history, unread counts and moderation), then fan out live over **Socket.IO** — `sendMessage` emits `chat:message:new` to each participant's `user:<id>` room via `emitToUser`; clients backfill history from the REST API and dedupe live events by message id

## Frontend Integration & Mock-Data Migration Rule

**The UI must look exactly the same after backend connection as it does on mock
data.** Every phase completes the same four-step migration for its screens:

1. **Seed** — the phase's mock data (mock files + localStorage stores) is
   migrated *verbatim* into MongoDB by an idempotent seeder registered in
   `backend/scripts/seed.js` (`node scripts/seed.js <name>` re-runs it safely
   anytime; running with no args runs every registered seeder).
2. **Wire** — screens switch to the shared client
   (`frontend/src/services/api.js`: base URL from `VITE_API_URL`, auto token
   attach, 401 → refresh → retry, typed errors). Where API shapes differ from
   what the UI renders, a mapper keeps the display identical (e.g.
   `toLegacyPet` renders "2 Years" / "8.4 Kg" exactly as before).
3. **Verify** — the phase check script passes AND the screens visually match
   their mock-data versions (same cards, same fields, same ordering).
4. **UI audit (mandatory before a phase is called done)** — grep every screen
   the phase covers for `localStorage`, mock imports and hardcoded arrays;
   also sweep **shared components** those screens render (headers, nav,
   pickers, badges). Anything still showing mock data on a covered screen =
   the phase is NOT done. Each phase file records the audit result.
5. **Remove** — only then are the mock files / localStorage keys deleted.

> Audit lesson (2026-07-18): shared components are where mock data hides —
> `TopHeader` kept greeting "Max" from dead localStorage after Phase 1 was
> "done", and ProductDetail's review cards/wire-a-review were still mock after
> Phase 3. Both caught by the retro audit below; the audit step is now
> mandatory per phase.

Seeders live in `backend/scripts/seeders/<name>.seed.js` and upsert by natural
keys (slug/name) so re-running never duplicates. Registered so far:
`demo-user`, `breeds`. Each phase below lists its seeder + the mock files it
retires.
